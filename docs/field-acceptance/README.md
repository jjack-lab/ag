# 现场验收包（8 小时协议）

这份包解决一件事：**让"视频到底准不准"有一个可复核的答案，而不是靠一段演示视频的口头结论。**

它不能替你做两件事：替你去牧场拍摄；替你判断模型能不能上生产。它只保证交付的资料齐全、自洽、可被第三方复查。

## 1. 什么时候用

- 你已经能跑通本地链路（`启动项目.bat` → 上传视频 → 看结果），现在要拿到第一组**非开发素材**的验收数字；
- 你要向评委/导师/合作牧场证明"我们量过，而且量得诚实"；
- 你准备开始一轮模型改进，需要一个冻结的对照基线。

## 2. 需要的人与设备

| 角色 | 人数 | 职责 |
| --- | --- | --- |
| 拍摄人 | 1 | 固定机位、完整录一圈，记录机位与圈舍编号 |
| 清点人 A / B | 2 | **各自独立**清点同一圈舍，互不通气，分别填写台账 |
| 记录人 | 1 | 汇总 CSV、导出视频结果、跑校验脚本 |

设备：一台能固定不动的相机或手机（建议三脚架）、一个能跑到 60 秒以上的连续录制、足够的存储空间、纸笔或离线表格（现场不要依赖网络）。

## 3. 8 小时流程

| 时段 | 内容 | 产出 |
| --- | --- | --- |
| 0:00–0:30 | 与牧场确认授权、圈舍编号、当日实际存栏来源（耳标/台账/系统） | 圈舍清单 |
| 0:30–1:30 | 架机位，录第 1 段（≥60 秒，覆盖整个圈舍，不移动机位） | `videos/clip-01.mp4` |
| 1:30–2:00 | A、B 分别清点，独立填写台账 | `pen-ledger.csv` |
| 2:00–3:00 | 换圈舍，重复拍摄；每个圈舍至少 1 段视频 + 1 次双人清点 | 多个 clip |
| 3:00–4:00 | 回场：把视频导入本机，跑识别，导出结果与报告 | `data/media/results/<job>` |
| 4:00–5:00 | 人工逐条判定：数错、漏检、ID 切换、区域进出是否成立 | `double-review.csv` |
| 5:00–6:00 | 汇总误差：清点差额、可判读率、误报数 | `report.md` |
| 6:00–7:00 | 跑校验脚本，补齐缺项 | 校验通过 |
| 7:00–8:00 | 复盘：哪些结论成立、哪些只能写"未验证" | 报告结论段 |

**时间不够时的降级方式**：只做 1 个圈舍、2 段视频、1 次双人清点。验收包依然有效，只是样本更小——报告里必须写清楚"仅 1 个圈舍，不能外推"。

## 4. 拍摄要求

- 机位固定，整段视频内不移动、不缩放；
- 每段 ≥60 秒；同一圈舍同一天至少 1 段；
- 画面完整覆盖该圈舍（四角都在画面内），或明确记录"未覆盖区域"；
- 分辨率短边 ≥480 像素；避免逆光和夜间无补光；
- 视频文件名即 `clip_id`，例如 `clip-01.mp4`；
- 同一段视频只服务一次验收，**不要复用参与过开发的素材**。

## 5. 台账要求

- `expected_count` 必须写清来源（耳标台账 / 牧场系统 / 当班记录），填在 `notes`；
- A、B 两人**独立**清点，不得商量后填同一个数；
- `gate_log_checked` 表示是否核对过当日出入栏记录，填 `yes`/`no`，填 `no` 时校验脚本会给提醒；
- 清点数为 0 也要填 0，不要留空。

## 6. 双人复核口径

每条复核记录回答一个问题：**这段视频里，系统的这个结论成立吗？**

- `check_type` 取值：`pen_count`（盘点差额）、`gate_crossing`（穿线计数）、`zone_enter`（区域进入）、`behavior`（行为判读）；
- `verdict_a` / `verdict_b` 取值：`match`、`mismatch`、`unreadable`；
- 两人可看同一段视频，但**先各自写结论再比对**；
- 不一致的记录保留，不要改成一致——分歧本身是重要结果（校验脚本会把它们计为 `disagreements`）；
- `unreadable` 是合法结论：模糊、遮挡、出画都可以判"不可判读"，并写原因。

## 7. 交付目录

```text
field-acceptance-2026-10-27/
├─ videos/
│  ├─ clip-01.mp4
│  └─ clip-02.mp4
├─ shooting-list.csv      # 拍摄清单（含每个视频的 sha256）
├─ pen-ledger.csv         # 圈舍台账（双人独立清点）
├─ double-review.csv      # 双人复核记录
└─ report.md              # 验收报告（用 templates/report-template.md）
```

`sha256` 用下面任一方式生成：

```powershell
Get-FileHash .\videos\clip-01.mp4 -Algorithm SHA256
```

## 8. 校验

```powershell
& $env:AGRINEBULA_PYTHON scripts\check_field_acceptance.py --root data\field_acceptance\2026-10-27
```

脚本会检查：文件是否齐全、CSV 表头是否符合协议、每个视频是否存在且哈希一致、数字字段是否为整数、报告里是否还有 `TODO`。退出码 0 表示资料齐全。

**校验通过 ≠ 精度达标**。前者是资料完整性，后者看报告里的差额、误报数和可判读率。

## 9. 报告必须回答的四个问题

1. 本轮一共几个圈舍、几段视频、总时长多少？
2. 人工双人清点一致的圈舍有几个？不一致的差额是多少？
3. 系统给出的轨迹数/差额，与人工结论差多少？其中多少条属于漏检、多少条属于 ID 切换？
4. 哪些结论只能写"未验证"（例如疾病、跨圈舍外推、夜间表现）？

模板见 `templates/report-template.md`。**没有数字就写"未测量"，不要写"效果良好"。**

## 10. 常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 整段视频 0 轨迹 | 机型/机位超出模型训练分布；置信度阈值过高 | 记录为失败样例，不要删；先调阈值复测，再决定是否换机位 |
| 同一头牛多个 ID | 遮挡、交叉、机位变换 | 记为 ID 切换，单独统计 |
| 盘点差额与人工不符 | 拍摄未覆盖全圈舍 / 牛只重叠 / 人工数错 | 先确认覆盖，再复点；两者都写进报告 |
| 双人清点不一致 | 牛只走动、遮挡、计数口径不同 | 保留分歧，必要时第三人裁决并注明 |

## 11. 边界声明（不要删）

本验收包只用于评估"视频辅助线索"与"人工结论"的吻合程度。它不产生疾病诊断，不预测发病时间，也不能把单圈舍结果外推到其他牧场。
