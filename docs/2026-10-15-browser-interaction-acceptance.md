# 网页纠错、复核与下载交互验收（2026-10-15）

## 隔离方式

通过 SQLite `backup()` 将 `data/agrinebula.db` 复制到被忽略的 `data/verification/browser-acceptance.db`，以同一应用代码和真实视频文件在 `127.0.0.1:8001` 提供临时网页。Chrome 通过页面按钮交互；测试结束后关闭 8001，交付服务 8000/5173 仍运行。验收结果 JSON、截图及浏览器下载文件均在被忽略的 `data/verification/`，不进入正式数据。

## 浏览器操作与证据

1. 切换“视频识别”，从最近视频任务打开 ICAERUS 羊视频 `b6584849f10c403c8a1404e8f91748b8`。
2. 点击“暂停并绘制漏检框”，在视频画面拖拽；页面生成非零的草稿框。输入明确标记的隔离验收说明并保存。隔离 API 回读 `missed_detection`、`frame_index=0`、归一化非零框坐标，页面显示 1 条纠错。
3. 在“人工复核记录”里选择默认的“漏检 / 已确认”，填写说明并提交。隔离 API 回读 1 条记录，页面显示对应记录。截图 `data/verification/browser-correction-review.png` 是本机运行时产物，Git 不跟踪。
4. 在 Chrome 点击“下载结果视频”“轨迹 CSV”“导出纠错 CSV”。浏览器实际保存 20,311,146 字节 MP4、309 字节轨迹 CSV（2 行）和 384 字节纠错 CSV（1 行）。下载 MP4 的 SHA-256 与结果视频完全一致：`d3b0ef7ba12991b62f77926174ecab654895a37d8c6171eb965f85ed94818728`。

验收原始结构化记录：`data/verification/browser-interaction-acceptance.json`。交互后分别请求 8000 与 8001：正式 API 的纠错和复核列表均为 `[]`，隔离副本各有 1 条。随后停止 8001，确认 8000/5173 仍在监听。

## 结论与边界

纠错画框、人工复核保存和三项下载链路已在 Chrome 中操作并核对落盘。该测试验证产品交互和持久化，没有改善默认羊模型的漏检，也没有生成牧场真实盘点或疾病结论。隔离副本中的“已确认”仅是测试选项，不是牧场人员的现场确认。
