## 推荐实现范围 A

延续 React + Python 和现有多色样式，逐个补齐上表的软件交付。采用以下数据流：

1. 档案：新增 `GET /api/animals` 列表查询；详情继续使用已有个体档案及回访接口。编号只能来自人工关联；目录不把临时 Track ID 当耳标。
2. 告警：扩展前端列表参数，接通现有关闭接口；记录处置说明并回读历史。创建核查事项沿用既有任务 API，不重复建设另一套待办。
3. 统计：新增按日期汇总的 API，从完整数据库记录计算，不能仅聚合最近 20 个视频或最近 100 条列表。视频数、轨迹数、告警条数和已关联个体数分别标注；导出内容与筛选一致。
4. 工作台：展示最近视频任务、待办摘要和刷新按钮，完成识别后重新拉取对应数据。
5. 摄像头：使用浏览器权限与 MediaRecorder 录制有限片段，结束后通过现有视频上传接口识别；权限拒绝、无摄像头、未录制内容时给出可操作提示。录像只在用户点击后开始，停止或离开页面时释放设备。

摄像头录像是本机采集入口；持续 RTSP 接入、断流监控与长期存储属于另一交付单元，需要视频源和运行约定。消息推送需要确认渠道；疾病预测需要带诊疗真值的数据。当前软件补齐不能替代这些依赖。

## 备选范围

- B：只补齐现有页面与接口，不增加摄像头录像。变更更小，可先完成档案、告警、统计、工作台。
- C：同时建设持续视频监控。需额外定义视频源、分段存储时长、断流状态和重复告警策略，并有可访问源进行验收；不能用文件上传冒充持续监控。

用户已明确确认“按推荐范围全部实施”，采用 A，作为本轮实现依据。

## 验收标准

- 已关联动物能从独立档案页检索，回访可保存回读，点击访问记录能打开原视频。
- 关闭告警后，待处理列表和看板数量更新；已处理列表能看到说明与时间；刷新后保持。
- 统计按真实记录及明确时间口径汇总；跨越默认列表大小的数据不会遗漏；CSV 与筛选一致。
- 工作台能打开最近任务；新任务完成后刷新展示真实结果。
- 摄像头经授权后可预览、录制、停止并提交同一识别管线；无设备时明确提示，保留文件上传入口。
- 既有前后端测试、构建通过，浏览器逐项核查关键操作；写入演示记录采用隔离数据库。
