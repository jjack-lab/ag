# 星牧智控整合版设计

## 目标

在 `F:\new大创` 建立一个独立、可运行、可验证的牧场牲畜智能检测系统。E、F 两盘原项目只作为来源，不覆盖、不删除。

首期验收重点是功能可用：用户能通过浏览器上传图片或本地视频，使用 YOLO11 完成牲畜检测；视频任务可进行 ByteTrack 跟踪，并输出检测、轨迹、健康风险和报告文件。

## 版本来源

- 应用基线：`F:\大创\yolov8- 牧业-app-main\yolov8-main`
- 模型与实验来源：`E:\大创\WAID_YOLO11`
- 整合目标：`F:\new大创`

应用层以 F 盘 FastAPI、React、SQLite、视频任务和跟踪健康模块为基线。模型使用 E 盘 WAID4500 YOLO11s 最佳权重，并以 SHA-256 `46d734cba7553f31e89e739156f50e9a675b176f798c70159838497531771a64` 校验。

## 首期功能

1. 图片上传、YOLO11检测、带框结果预览与下载。
2. 本地视频上传、异步处理、进度查询与结果播放。
3. ByteTrack 持续跟踪和 Track ID 标注。
4. 轨迹 CSV、健康告警 CSV、个体健康汇总 CSV、HTML 报告导出。
5. 静止、疑似卧倒、离群、活动量下降和区域停留等规则型风险提示。
6. SQLite 保存任务、模型状态和告警记录。
7. React 控制台展示任务、进度、模型状态、视频及证据文件。
8. PowerShell 一键预检和启动。

健康结果是辅助筛查和风险提示，不是兽医疾病诊断。

## 代码与数据边界

迁入自研应用包、API入口、健康规则、测试、React源码、配置、文档和交付脚本。迁入一个经过哈希验证的模型文件及少量验收媒体。

不迁入虚拟环境、`node_modules`、Python缓存、pytest缓存、完整训练集、历史输出、旧数据库、整套第三方 Ultralytics 源码或旧 PyQt 桌面端。运行产生的数据统一保存到新项目 `data/` 和 `outputs/`。

## 运行架构

React 前端调用 FastAPI。图片请求同步返回结果；视频请求创建后台任务，由媒体处理器调用 YOLO11 和 ByteTrack，逐帧写出带框视频、轨迹和健康规则结果。SQLite 记录任务状态及告警，FastAPI 以静态资源接口提供结果文件。

所有项目路径由项目根目录推导。Python 可通过 `AGRINEBULA_PYTHON` 指定；模型可通过环境变量覆盖，但默认必须使用 `models/detection/yolo11s-waid.pt`。不得依赖 E、F 原项目的绝对路径。

## 错误处理

- 启动预检模型、Python、Node/npm和前端清单。
- 模型缺失或哈希不符时停止并给出明确诊断。
- 上传不支持或损坏的媒体时返回可理解的错误。
- 视频任务失败时保留失败状态和错误信息，不伪装为完成。
- GPU不可用时支持通过配置改用CPU，不静默吞掉推理错误。

## 验收标准

1. 后端单元和交付测试通过。
2. 前端测试与生产构建通过。
3. 启动脚本 `-CheckOnly` 通过。
4. API健康检查和模型状态接口返回正常。
5. 一张真实 WAID 图片能生成带框结果。
6. 一段真实视频能完成任务并生成带 Track ID 的视频。
7. 轨迹、告警、健康汇总和HTML报告均存在且可读取。
8. 新项目运行时不需要从 E、F 原项目读取代码、模型或数据。
