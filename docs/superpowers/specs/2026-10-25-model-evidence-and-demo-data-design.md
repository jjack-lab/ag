# 独立模型验证与演示数据设计

日期：2026-10-25。用户确认先提高图一、图二的模型表现，再写入图三、图四的演示数据；羊检测选择独立验证优先。

## 目标与顺序

1. 保留现有羊检测 2 TP / 1,954 FN 的 ICAERUS 开发样例基线，不以同项目羊专用模型在该视频上的结果冒充独立提升。
2. 用不同来源、带逐帧框标注的 AUTH-Sheep 视频冻结独立评测集，核对来源、文件摘要、标注坐标和帧对齐。先比较当前交付模型与候选，报告 Precision、Recall、F1、每视频差异和未检出示例。候选模型许可及训练集交叠核查完成前，只在研究环境使用，不纳入交付权重。
3. 牛行为使用既有 CBVD4 多 seed 开发集结果分析弱类“站立反刍”；在开发集选择候选，并用新来源的保留视频确认。已读过的 CBVD-5 正式 test 只作历史结果，不能再参与阈值、模型选择或推广判断。未达到逐类推广门槛时，网站仍显示原始跨域失败证据及候选研究结果，不替换默认权重。
4. 模型阶段完成后，以显式命令向隔离或用户指定的 SQLite 数据库写入少量可重复的模拟档案、关联和盘点记录。页面必须清楚标记“模拟数据”，不得与现场核对台账混淆；清理命令只删除本脚本创建的记录。

## 组件与数据流

- `scripts/` 的独立评测准备器从 AUTH-Sheep 官方文件读入 HBB 标注，转换为项目已有评测格式，并保存 DOI、文件哈希、帧范围及转换清单。视频和大文件保存在被 Git 忽略的数据目录。
- 模型评测器复用现有检测与匹配指标，不修改历史评测卡片；每个候选输出独立 JSON/CSV 和来源说明。只有独立数据集上的结果满足预先写定的改善目标和误报边界，才考虑在网页提供显式候选选项。
- 行为实验沿用现有 cross-domain worktree 的训练、汇总和校验入口。实验工件与交付模型分离。
- 演示数据种子器通过现有 API 或仓储接口创建记录，使用固定前缀和来源字段；重复执行不会增加记录数。正式业务记录不被删除或覆盖。

## 验收边界

- 羊检测以框级 IoU≥0.5 的 Recall 和 F1 相对基线改善为主，同时报告 Precision 与不同视频的波动；不预设能达到某个未经测量的数值。
- 牛行为以来源隔离的 Macro-F1 和最弱类 F1 为主；推广仍要求 Macro-F1≥0.70 且每类 F1≥0.60，并需新的独立确认集。不能按既有 test 结果事后改选 Kinetics 臂。
- 模拟档案和盘点只能验证页面流程与空状态切换，不构成牛只身份、存栏、健康或模型精度证据。
- 若独立数据无法获取、权利信息不足或新确认集缺失，阶段状态明确记为待数据，不伪造评测与推广结论。

## 已知限制

AUTH-Sheep 官方记录提供四段视频及 HBB JSON，合计约 2.3 GB；当前沙盒 DNS 无法解析 Zenodo。官方页面的许可证字段未给出明确文本，获取前需记录权利状态；不在仓库提交视频、标注或第三方权重。已有 CBVD4 test 曾部分暴露于更早的研发记录，不能充当新的前瞻性确认集。
