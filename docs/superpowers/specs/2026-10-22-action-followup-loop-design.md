# 视频处置与复查闭环设计

## 目标

把已完成视频中的观察结果转为人工可执行、可追溯的核查事项。首版支持创建、分派、记录处理、安排复查与关闭，并从事项返回原视频证据。它是科研原型中的任务管理，不给出疾病诊断。

## 现状与边界

现有 React 工作台可重开视频、显示带时间点的事件、保存纠错与人工复核；FastAPI 和 SQLite 保存任务与记录。首页历史规则告警不绑定视频任务，因此不能把它们直接作为可跳转的视频待办来源。首版从已完成视频结果页手工创建事项，可填写视频内 Track ID 和时间点；二者只用于本段视频定位。不会把同一 Track ID 当跨天个体，也不会自动把全部规则提示转为待办。

## 数据与状态

`action_tasks` 保存 `id/job_id/species/title/track_id/time_seconds/assignee/due_at/status/created_at/updated_at`。`action_task_updates` 追加保存 `task_id/status/actor/note/next_due_at/created_at`，保留完整处置历史。状态为 `pending`（待核查）、`in_progress`（处理中）、`followup`（待复查）、`closed`（已关闭）。创建时为 `pending`。更新必须填写操作人和记录说明；转到 `followup` 必须填写下一次复查时间；关闭必须填写结论说明。重新打开关闭事项允许，且留下新更新记录。逾期只按未关闭事项的当前 `due_at` 与本地当前时间比较，不存冗余布尔值。

## API 与页面

- `GET /api/action-tasks`：按状态、负责人筛选，默认最新在前；每条带处置历史及绑定视频是否可打开。
- `POST /api/action-tasks`：仅允许绑定已完成视频；标题、负责人和复查日期必填；可选 Track ID 和非负秒数。Track ID 是人工填写的本视频定位线索。
- `POST /api/action-tasks/{id}/updates`：写入追加式状态更新；服务端负责状态与到期日校验。
- 视频结果页提供“创建核查事项”表单及本视频事项列表。工作区新增“处置待办”页，展示待处理、逾期、待复查数量与可筛选列表；每条可打开原视频，查看处置历史并记录下一步。

## 验收

在隔离 SQLite 中用现有已完成牛视频走通创建 → 处理中 → 待复查 → 关闭，刷新后记录仍在，点击事项回到同一视频；无效视频、Track ID、时间和状态更新被拒绝。前后端自动化测试及构建通过，正式数据库不写入演示记录。第二项视频质量提示和第三项巡检摘要在此闭环稳定后分别设计与实施。
