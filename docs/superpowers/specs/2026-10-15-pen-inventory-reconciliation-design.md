# 圈舍存栏核对与丢失风险记录设计（建议稿）

## 目标与证据边界

首版让牧场人员围绕一段已完成的牛或羊视频，登记圈舍台账数量、拍摄覆盖和现场清点数量，形成可追溯的差额待办。视频的 Track ID 只作回看线索，不进入存栏数量计算。尤其是现有默认羊模型在 ICAERUS 样本上 Recall 仅 0.102%，不可用它断言“少了几只”。

## 候选路线

1. **圈舍数量核对（推荐）**：运营人员已有台账和现场清点流程，可先交付差额待办；误报控制依靠覆盖、复点、出入栏核对及人工签名。不能自动指出是哪只动物。
2. **耳标逐只核对**：能定位个体，但须先有耳标真值、跨天关联及机位验收；现有视频数据不足以自动完成。
3. **直接以视频 Track ID 计数**：开发成本低，但单段视频的遮挡、漏检、重复 ID 与镜头移动会导致错误丢失提醒；当前实测明确不满足验收要求，不采用。

## 记录与状态

- 每条盘点记录绑定一段已完成视频，保存 `job_id`、视频物种、圈舍编号、盘点日期时间、台账期望数量及其来源说明、现场清点数量（可暂缺）、覆盖状态（完整／不完整／未知）、覆盖说明、录入者和创建时间。后续复点以追加记录保留，不覆盖原始条目。
- 覆盖不完整或未知时，状态始终为“待补拍／覆盖待核对”，即使手填数量较少，也不推断短少。
- 覆盖完整但未现场清点时，状态为“待人工清点”。两数相等时只称“本次清点数量一致”；不保证视频识别完整或每只动物身份不变。
- 覆盖完整且现场数与台账数不等时，显示差额和“待现场复点”，不自动写“丢失”。多出的数量也作为台账差异待核实。
- 现场复核是单独的追加事件：记录复点数量、操作人、时间、是否核对出入栏记录、现场检查说明和结论。复点后数量一致可标“已核平”；若仍短少，标“复点仍短少、原因待查”。只有操作人明确登记丢失数量、已核对出入栏并完成现场寻找时，显示“人工登记丢失”，同时标注 `user_recorded`，不冒充系统自动确认。
- 未提供单只价值或真实损失单据前，不生成自动经济损失金额。页面可显示待核对数量和人工登记数量，便于优先安排人员。

## 产品流程

在已完成的视频结果中加入“圈舍盘点”入口，左侧输入台账及覆盖／清点信息，右侧显示视频来源、视频内 Track ID 数及明确的参考警示；保存后呈现状态、差额与下一步动作。所有历史盘点在同一工作区按日期列出，可打开视频证据。异常需现场复点并登记出入栏核对；状态和审计记录在重启后仍保留。

## 接口、校验与验收

- 新增独立存储表与 API，不复用健康告警或临时 `cattle_id`。已完成视频才能创建盘点；物种取任务结果，不允许牛羊混填。数量为非负整数；完整覆盖必须有覆盖说明；确认丢失需现场复点、出入栏核对、寻找记录、操作人及数量，丢失数不得超过复点短少数。
- API 响应同时给出输入原值、派生状态、差额、视频任务链接和审计事件。前端只展示 API 派生状态，避免两套规则漂移。
- 测试至少覆盖：漏拍优先于差额、清点 0 与未清点有区别、差额不能自动变丢失、复点核平、人工登记丢失的必填证据、跨物种/失败任务拒绝、持久化重启、浏览器表单及状态展示。
- 使用隔离数据库和既有公开开发视频做交互验收，只验证工作流，不声称模型可用于实际牧场自动盘点。真实牧场试点需要完整覆盖的视频、现场台账与操作者复核记录。
