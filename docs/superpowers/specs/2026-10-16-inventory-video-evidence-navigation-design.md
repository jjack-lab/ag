# 圈舍盘点视频证据导航设计

## 目标

让操作人员从“圈舍盘点”的历史记录直接回到该盘点绑定的视频任务，查看结果视频、轨迹、健康证据、人工复核和该视频的盘点记录。该操作只导航和读取，不修改盘点或视频数据。

## 交互

- 全局“圈舍盘点”页的每张历史盘点卡片显示“打开视频证据”。
- 点击后读取记录的 `job_id` 对应视频任务。
- 成功时切换到“实时监控”，将识别工作台切到视频模式，加载该历史任务，并滚动到结果播放器。
- 视频任务不存在、未完成或请求失败时，保留在盘点页，并在盘点面板显示明确错误；不清空当前列表。
- 已经在某个视频结果下显示的盘点卡片不重复显示导航按钮，避免打开当前任务的无意义操作。

## 组件边界与数据流

1. `InventoryPanel` 只负责显示记录并通过 `onOpenVideo(jobId)` 上报用户意图，不自行控制工作区导航。
2. `App` 负责调用 `fetchVideoJob(jobId)`、处理加载错误、切换工作区，并保存要打开的 `VideoJob`。
3. `RecognitionStudio` 接收外部选择的视频任务；任务变化时切换到视频模式、展示该任务结果，并保持原有上传、历史任务、复核、纠错与盘点组件不变。
4. 成功加载后由 `App` 滚动到识别工作台；错误由 `InventoryPanel` 的外部错误属性显示。

这种分工避免盘点组件直接操纵页面导航，也避免在盘点页复制视频播放器和复核组件。

## 状态与错误处理

- 打开期间禁用该卡片的按钮并显示加载状态，防止重复请求。
- 只接受 `status=completed` 且存在 `result` 的视频任务；其他状态显示“视频任务尚未完成，暂不能打开证据”。
- 404、网络错误和响应格式错误使用接口返回的信息或统一的“视频证据加载失败”。
- 新请求到达时，以最后一次点击的任务为准，避免较慢的旧请求覆盖新选择。

## 测试与验收

- `InventoryPanel` 测试：全局列表显示按钮；视频内嵌盘点不显示按钮；点击上报正确 `job_id`；加载错误可见。
- `App`／`RecognitionStudio` 测试：点击后请求对应任务，切换到实时监控与视频模式，播放器使用该任务的结果地址。
- 失败测试：不存在或未完成任务不切换页面，并显示错误。
- 前端全量测试和生产构建必须通过；使用正式数据库已有历史视频任务做浏览器导航验收，但不写入新的盘点、复核或告警记录。

## 范围边界

- 本次不增加盘点分页、筛选或搜索。
- 本次不改变视频处理、模型推理、盘点状态规则和数据库结构。
- 本次不把视频 Track ID 解释为存栏数或永久身份。
