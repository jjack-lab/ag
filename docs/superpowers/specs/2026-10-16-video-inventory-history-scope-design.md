# 视频结果内盘点记录按任务查询

## 目标

打开任意已完成视频时，结果页中的“圈舍存栏核对”显示该视频绑定的所有盘点记录，即使这些记录已被后来超过 100 条全局记录挤出旧接口窗口。全局“圈舍盘点”的分页和筛选行为维持现状。

## 接口

保留 `GET /api/inventory-checks` 原有无参数行为（最近 100 条数组）。可选 `job_id` 参数提供按视频任务过滤的完整数组；查询使用参数化 SQL 并按 `created_at DESC, id DESC` 排序。空任务 ID 返回 422；不存在或无盘点的任务返回空数组。响应字段及人工状态计算与原接口一致。

## 页面

嵌入视频结果的 `InventoryPanel` 请求 `/api/inventory-checks?job_id=<当前任务ID>`；全局历史仍请求分页接口。提交新盘点或人工复核后，当前视频内的列表保持可见并更新。当前视频面板不出现全局筛选与翻页控件。

## 验证

后端以超过 100 条较新的其他任务记录构造回归场景，核对旧无参接口确会截断、带 `job_id` 的接口仍返回旧视频记录且不混入其他任务。前端测试核对请求任务 ID、列表和全局接口互不干扰。隔离 SQLite 浏览器验收旧视频结果页，正式数据库不写入测试记录。
