# 行为模型接入第一阶段设计

## 目标

把现有训练产物 `outputs/cvb_x3d_v2/best.pt` 作为研究演示模型接入星牧智控主应用，完成“牛只检测、轨迹跟踪、时序行为识别、结果视频、结构化统计、前端展示”的离线视频闭环。

本阶段如实保留当前模型约 `0.219` 的 Macro-F1 限制。行为识别结果只作为实验性观察证据，不新增自动健康告警，不用于疾病诊断。后续数据平衡与重新训练作为独立阶段实施。

## 范围

本阶段包含：

- 将 `cloud_pack` 中已验证的 CVB 标签、X3D 构建和安全检查点加载能力迁入主应用包。
- 为每个视频内 `track_id` 缓存单牛裁剪帧并执行 16 帧 X3D 推理。
- 对相邻窗口的预测进行时间平滑和低置信度降级。
- 在结果视频叠加 Track ID、中文行为和置信度。
- 生成逐窗口行为时间线与逐轨迹行为汇总。
- 通过任务 API 返回行为模型状态、版本、产物路径和汇总数据。
- 在现有 React 识别结果区展示行为统计、模型信息和下载入口。
- 行为模型不可用时保留现有检测、跟踪和规则健康分析能力。

本阶段不包含：

- 重新训练或调参。
- 新增行为健康告警规则。
- RTSP、USB 摄像头或实时推流。
- 跨视频、跨摄像头身份识别。
- 将 Track ID 解释为永久牛只身份。
- 具体疾病诊断。

## 方案选择

采用“将训练包中的稳定模型能力提升到主应用，再建立独立运行时与报告模块”的方案。

不让主应用直接导入 `cloud_pack`，因为训练交付包不是稳定的运行时依赖，直接引用会造成部署路径耦合和版本漂移。也不在本阶段统一重构全部数据准备、训练和推理目录，避免扩大首轮接入范围。

## 系统架构

处理链路为：

`视频解码 -> YOLO 检测 -> ByteTrack/BoT-SORT 分配 ID -> 单轨迹裁剪缓冲 -> X3D 行为分类 -> 时间平滑与置信度门控 -> 视频绘制和行为报告 -> API -> React 展示`

模块边界如下：

1. 模型模块负责 X3D 构建、检查点元数据验证和安全加载，不处理视频。
2. 行为运行时按 `track_id` 管理帧缓冲、预处理、推理和平滑，对外只返回结构化预测。
3. 跟踪流水线负责把检测框裁剪为单牛画面，并把预测绘制到结果帧。
4. 报告模块负责把预测转换为时间线和汇总，不依赖模型对象。
5. 模型注册器负责解析权重位置、SHA-256、版本和可用状态。
6. API 和前端只消费序列化结果，不理解模型内部实现。

这些边界允许后续更换模型或重新训练权重，而不重写视频任务和页面。

## 模型安装与注册

安装时将 `outputs/cvb_x3d_v2/best.pt` 复制为 `models/behavior/cvb_x3d_v2_best.pt`，不移动、不删除或覆盖原训练产物。

默认路径可被环境变量覆盖。行为模型注册结果包含：

- 名称与模型版本。
- 绝对路径。
- SHA-256。
- `ready`、`unavailable` 或 `failed` 状态。
- 不可用或失败原因。

缺少默认权重不阻止应用启动。显式配置了不存在或无效的权重时，也只关闭行为分支并暴露原因。

模型加载必须使用受限的 `torch.load(..., weights_only=True)`，严格验证格式版本、架构、12 类顺序、16 帧输入规格和状态字典兼容性。

## 行为运行时

每个活跃 `track_id` 维护独立的裁剪帧队列。裁剪框在边界内扩展 15% 上下文，随后按训练输入规范转换为 224×224。队列达到 16 帧后触发预测；相邻推理窗口允许重叠，以避免行为更新过慢。

运行时输出至少包含：

- Track ID。
- 视频时间和帧号。
- 原始类别与显示类别。
- 中文显示名。
- 置信度。
- 是否属于可靠健康行为。
- 模型版本。

同一轨迹的相邻概率进行时间平滑。置信度低于运行时配置阈值时统一输出“无法确定”。`none`、`other`、`hidden` 无论置信度如何都统一显示“无法确定”，且不进入有效行为统计。

轨迹不足 16 帧、检测框过小、裁剪无效或没有足够连续画面时不强行预测。首版不跨 Track ID 合并缓冲或统计。

## 输出产物

每个完成的视频任务新增：

### `cattle_behavior.csv`

逐行为窗口记录：

- `frame_index`
- `timestamp_seconds`
- `track_id`
- `class_id`
- `behavior_name`
- `behavior_display_name`
- `confidence`
- `health_eligible`
- `model_version`

### `cattle_behavior_summary.csv`

逐 Track ID、逐显示行为记录：

- `track_id`
- `behavior_name`
- `behavior_display_name`
- `duration_seconds`
- `eligible_ratio`
- `uncertain_duration_seconds`
- `model_version`

`eligible_ratio` 的分母只包括该轨迹的明确、可靠行为时长；无法确定时长单独记录，不用它稀释有效行为占比。如果某轨迹没有可靠行为，则比例为 `0`。

现有追踪视频、轨迹 CSV、告警 CSV、健康汇总 CSV 和 HTML 报告全部保留。结果视频在牛框附近绘制 Track ID、行为中文名和置信度；没有可靠预测时绘制“无法确定”。

## API 与前端

`/api/models` 增加行为模型状态、版本和 SHA-256。视频任务结果增加：

- `behavior_csv`
- `behavior_summary_csv`
- `behavior_model_status`
- `behavior_model_version`
- `behavior_model_error`
- `behavior_summary`

前端在现有结果视频下方展示：

- “研究演示模型”提示和模型版本。
- 按 Track ID 分组的行为时长与占比表。
- 无法确定时长。
- 行为时间线和汇总 CSV 下载入口。
- 行为模型未加载或运行失败的非阻断提示。

前端继续使用“Track ID”或“视频内 ID”措辞，不将其显示为永久牛只编号。现有健康报告、轨迹和告警下载入口不变。

## 容错与降级

- 权重缺失或元数据不兼容：行为状态设为 `unavailable`，原任务继续。
- CPU/CUDA 加载失败：记录原因；允许配置的 CPU 降级，仍失败则关闭行为分支。
- 单次行为推理异常：只记录一次错误，状态设为 `failed`，停止该视频后续行为推理，继续生成原有结果。
- 轨迹片段不足或裁剪失败：该窗口输出“无法确定”，不终止任务。
- 输出行为 CSV 失败：任务保留原有产物，并在行为错误字段中说明失败原因。
- 结果视频编码失败：沿用现有任务失败策略；已经生成的结构化错误信息应保留。

行为错误不得被误报为健康风险，行为失败也不得删除已经生成的追踪和健康产物。

## 测试与验收

采用测试驱动实现。

### 模型层

- 验证 12 类不可变顺序、16 帧和 224×224 输入规格。
- 验证实际 `best.pt` 可被安全加载，并校验版本与 SHA-256。
- 验证缺失、损坏或不兼容权重被安全拒绝。

### 运行时层

- 验证不同 Track ID 的缓冲互不污染。
- 验证裁剪扩展与边界钳制。
- 验证未满 16 帧不推理。
- 验证概率平滑、低置信度门控和三个不确定类别映射。
- 验证输出可 JSON 序列化。

### 集成层

- 使用确定性假模型处理短视频，同时生成原有追踪产物和两份行为 CSV。
- 验证行为汇总时长、占比和不确定时长计算。
- 验证行为模型缺失或推理失败时视频任务仍完成。
- 验证 API 模型状态和任务结果字段。

### 产品层

- 验证前端显示模型版本、研究提示、逐轨迹行为统计和下载链接。
- 验证未加载与失败提示不会遮挡结果视频和原有下载项。
- 运行完整 Python 测试、React 测试和 React 生产构建。
- 使用一段真实牛只 MP4 做本地上传验收，确认结果视频、CSV 和页面均可使用。

## 完成标准

满足以下条件时，本阶段完成：

1. 默认安装的 `cvb_x3d_v2_best.pt` 能被主应用识别并报告准确哈希和版本。
2. 上传视频能够生成带 Track ID、行为中文名和置信度的结果视频。
3. 行为时间线与汇总 CSV 可下载，API 返回 JSON 安全的行为汇总。
4. 前端能按视频内 Track ID 展示行为时长、占比、无法确定时长和研究提示。
5. 行为模型缺失、损坏或推理失败时，现有检测、跟踪和规则健康分析仍能完成。
6. 所有相关自动化测试、完整回归测试和生产构建通过。
7. README 记录模型指标限制、安装位置、SHA-256、使用方式和“实验结果，不是疾病诊断”的边界。

## 后续阶段

完成接入后，下一阶段单独处理训练质量：复核分组划分与测试集类别覆盖、控制不确定类别比例、补足稀有类、重新训练并以 Macro-F1 和逐类召回率选模。只有在真实独立测试集达到可接受指标后，才设计“行为异常 + 轨迹异常”的联合健康告警。
