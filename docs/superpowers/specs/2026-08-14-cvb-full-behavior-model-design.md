# CVB 全行为视频识别模型设计

## 目标

在 `F:\new大创` 中实现可运行的逐牛视频行为识别能力。用户上传 MP4 后，系统复用现有 YOLO 检测和 ByteTrack 跟踪，为每头牛输出稳定 ID、行为中文名、置信度、带标注结果视频和行为时长统计，并将可靠的行为统计提供给现有健康风险筛查模块。

首版训练 CVB 提供的全部 12 个标签：`none`、`grazing`、`walking`、`ruminating-standing`、`ruminating-lying`、`resting-standing`、`resting-lying`、`drinking`、`grooming`、`other`、`hidden`、`running`。其中 `none`、`other`、`hidden` 参与训练，但产品界面统一显示“无法确定”，且不进入健康风险统计。

首版仅保证上传本地 MP4 后离线分析。摄像头、RTSP 和 VLM 不在本次实现范围内，但行为推理接口应允许后续接入。

## 已确认环境与约束

- 项目：`F:\new大创`，Git 分支 `integration`。
- 数据：`F:\CVB_dataset\000058916v001\data`，训练过程中只读使用。
- Python：`F:\deepl\anaconda1\envs\pytorch\python.exe`。
- 已确认 PyTorch 2.0.0、CUDA、Ultralytics 和 OpenCV 可用。
- GPU：NVIDIA GeForce RTX 4060 Laptop GPU，8 GB 显存。
- 检测权重：首版复用 `F:\new大创\models\detection\yolo11s-waid.pt`，不重新训练检测器。
- 数据集存在少量未完成或损坏文件时，训练准备必须过滤它们，不得删除已完成数据。

## 方案选择

采用“YOLO + ByteTrack + 逐牛短片段 X3D 分类”方案。

没有选择 AVA/SlowFast 端到端行为检测，因为其训练和 Windows 部署复杂、显存压力较大，不利于优先交付功能。没有选择单帧分类，因为它难以区分站立反刍与站立休息等依赖时间变化的行为。

## 系统架构

处理链路如下：

`视频解码 -> YOLO 牛只检测 -> ByteTrack 分配 ID -> 按 ID 缓存连续帧 -> X3D 行为分类 -> 时间平滑 -> 结果视频与行为统计 -> 健康风险筛查`

模块边界：

1. 检测模块只输出牛只框、检测置信度和帧时间。
2. 跟踪模块将检测框关联为短期稳定的 `track_id`。
3. 轨迹裁剪模块按 `track_id` 维护帧缓冲区，并在牛框周围保留 15% 上下文。
4. 行为模型接收固定长度的单牛片段，输出 12 类概率。
5. 时间平滑模块对同一 `track_id` 的相邻预测做平滑，降低标签抖动。
6. 聚合模块生成每头牛的行为时长、占比和无法确定比例。
7. 健康模块只消费 9 个明确行为的可靠统计，不把不确定输出当作健康证据。

跟踪 ID 是视频内临时身份，不等同于牛只永久身份。发生 ID 丢失或切换时，首版不跨轨迹强行合并统计。

## 数据与标注

CVB 已提供 COCO 风格牛框、`track_id`、逐实例 `behavior` 属性，以及 AVA 格式训练/验证文件，因此无需重新人工逐帧画框。

数据准备流程：

1. 解析 `behaviour_list.pbtx`、`ava_train_set.csv` 和 `ava_val_set.csv`。
2. 将 AVA 框与 `raw_frames` 中的连续帧对应起来，为单头牛生成时序样本索引。
3. 每个样本覆盖约 2 秒，均匀采样 16 帧，裁剪并缩放为 224 x 224。
4. 裁剪框周围保留 15% 环境上下文，以支持饮水和采食等场景相关行为。
5. 排除存在 `.aria2` 状态、无法解码、连续帧不足、框过小、越界严重或标签未知的样本。
6. 不复制完整原始数据；生成可复现的索引清单、质量报告和必要缓存。

数据划分必须按原始视频或片段组完成，不按单帧随机划分。官方训练组用于训练，并按组划出内部验证集；官方验证组保留为最终测试集。同一原始片段不得跨集合，质量报告必须明确给出分组泄漏检查结果。

输出的数据报告至少包含：每类样本数、每集合样本数、过滤原因计数、损坏路径、分组泄漏结果和每类可视化抽样。类别不均衡通过加权采样或类别权重处理，具体方式由数据分布决定，但只能启用一种主要重平衡机制，避免重复过度补偿。

## 模型与训练

使用 Kinetics-400 预训练的轻量 X3D 作为时序骨干，将分类头替换为 12 类输出。

训练分为两个阶段：

1. 冒烟训练：使用小规模、覆盖全部类别的数据运行少量迭代，验证数据读取、前向/反向传播、显存、指标和权重保存。
2. 正式训练：先冻结部分骨干训练分类头，再逐步解冻微调；启用 CUDA 混合精度、梯度累积、早停、最佳权重保存和断点续训。

RTX 4060 8 GB 的初始物理批量设为 4；如果显存允许可提高，如果发生显存不足则降低批量并相应调整梯度累积。所有实际超参数写入独立配置并随训练产物保存，不在代码中散落硬编码。

模型选择指标为内部验证集 Macro-F1。训练报告同时输出总体准确率、Macro-F1、每类 Precision/Recall/F1、混淆矩阵、损失曲线和学习率曲线。官方测试集只在选定最佳模型后运行一次，避免用测试结果反复调参。

模型产物保存到 `F:\new大创\models\behavior`，训练日志、配置、报告和图表保存到 `F:\new大创\outputs\training`。权重元数据必须记录类别映射、输入规格、训练配置、数据版本和指标。

## 推理与项目集成

上传 MP4 后，系统逐帧运行现有 YOLO 和 ByteTrack。每个活跃轨迹维护固定长度的裁剪帧队列；队列达到 16 帧后触发行为推理。行为结果在时间窗口内平滑，低于配置阈值的输出统一记为“无法确定”。

结果视频在每头牛框旁显示：视频内跟踪 ID、中文行为名称和置信度。分析结果还应提供每头牛各明确行为的累计时长与占比、无法确定比例、模型版本和推理配置。

现有 CSV/HTML 报告继续保留，并增加行为字段。健康风险模块消费平滑后的可靠行为统计，与现有轨迹和持续时间规则结合；输出必须继续表述为风险筛查，不作为疾病诊断。

## 容错与降级

- 行为权重缺失或加载失败：原有 YOLO、跟踪和规则分析继续可用，并明确返回“行为模型未加载”。
- 单帧损坏：跳过该帧并记录，不中断整段视频。
- 轨迹片段不足：不强行预测，显示“无法确定”。
- 行为置信度过低：显示“无法确定”，不进入健康统计。
- 跟踪 ID 切换：不同轨迹分别统计，不自动认定为同一头牛。
- GPU 显存不足：降低行为推理批量；若 CUDA 不可用，允许 CPU 降级并提示速度下降。
- 输出视频编码失败：保留结构化行为结果和错误信息，避免整次任务无结果。

## 验证与验收

### 数据层

- 12 类映射与 `behaviour_list.pbtx` 一致。
- `.aria2`、损坏帧和非法框被过滤并报告。
- 同一来源组不跨训练、验证和测试集合。
- 每个集合和类别均有可审查统计。

### 模型层

- 模型输入为 16 帧单牛片段，输出维度为 12。
- 冒烟训练可以完成前向、反向、保存和重新加载。
- CPU 与 CUDA 均能加载权重并产生概率输出。
- 正式报告包含 Macro-F1、逐类指标和混淆矩阵。

### 端到端层

- 用户上传 MP4 后能生成带牛框、跟踪 ID、行为和置信度的结果视频。
- 页面能展示逐牛行为时长和无法确定比例。
- CSV/HTML 报告包含行为模型版本和结构化行为结果。
- 行为模型缺失时原有功能仍可运行并提供清晰提示。
- 页面相关按钮可触发，API 与前端错误状态可见。

首轮验收重点是完整、稳定、可复现地跑通 12 类训练和上传视频分析链路。模型指标按真实测试结果报告；不预设无法验证的准确率承诺。个别稀有类别如果样本不足或召回率偏低，必须在报告中明确说明。

## 后续扩展
