# 星牧智控：5 分钟答辩演示脚本

## 演示前准备

1. 运行 `启动项目.bat`，确认启动预检显示项目版本且网站可打开。
2. 准备一段有授权的牛视频；若使用仓库的开发演示视频，开场直接说明“这是开发素材，用于演示流程，不代表牧场验收结果”。
3. 提前在 `web/.env` 设置 `VITE_CATTLE_DEMO_JOB_ID`，或准备现场上传；确认本机 API 已启动、结果视频可播放、打印机可选“保存为 PDF”。
4. 打开 `http://127.0.0.1:5173/workbench.html#/modules`。演示不修改冻结 test 集或正式验收数字。

## 0:00–0:45 上传并识别

**操作**：进入“视频识别”，上传牛视频；若处理需要等待，打开已完成的同一段演示任务。

**说什么**：“系统把一段视频转成检测、视频内轨迹和可回看的结果。这里的 Track ID 只在这段视频内有效。”

**不说什么**：不称 Track ID 为永久牛只身份，不称识别到的数量为真实存栏数。

## 0:45–1:35 展示证据链

**操作**：打开结果视频，选一条轨迹，展示对应时点、原帧或片段，以及行为摘要。

**说什么**：“每条提示都能回到原视频。遮挡、出画和‘无法确定’片段需要人工再看。”

**不说什么**：不把裁剪放大称为图像增强或自动纠错，不说行为模型能诊断疾病。

## 1:35–2:35 查看核查优先级

**操作**：进入“健康模型分析”，选同一任务，指向优先级徽章、“为什么被标出来”和“下一步”卡片。

**说什么**：“规则把需要先核查的轨迹排在前面，并标出触发时点。优先级只决定查看顺序；行为模型是旁证。”

**不说什么**：不把优先级说成疾病概率，不把‘中’说成临床风险等级，也不保证这 26 条都是真异常。

## 2:35–3:30 人工复核

**操作**：回到视频证据，示范记录一条“已确认 / 误报 / 仍待判断”的人工结论，并指出操作人、时间与备注。

**说什么**：“现场人员的判断与模型结果分别保存，误报不会被悄悄改写成模型正确。”

**不说什么**：不把演示录入的结论当作真实牧场记录；演示前后核对 `DEMO-` 标识。

## 3:30–4:25 摘要与报告

**操作**：打开健康报告或巡检摘要，指认视频来源、规则证据、行为旁证、人工复核和适用边界。

**说什么**：“交接时能看到结论从哪里来、谁复核过、哪些仍未验证。”

**不说什么**：不称它为兽医诊断书或疾病预测报告。

## 4:25–5:00 打印与收束

**操作**：浏览器打印，选择“保存为 PDF”，查看分页与中文显示。

**说什么**：“这份报告可以交给下一班继续核查。真正的现场效果要用新牧场视频和双人清点记录测量；验收方法已在 `docs/field-acceptance/`。”

**不说什么**：不把开发视频的结果或模拟数据说成现场精度、误报率或经济收益。

## 如果现场链路失败

- API 未启动：展示预先保存的同任务截图和视频文件，明确说“现场服务未连通，本次只展示既有结果”。
- 视频还在处理：切换到预先完成的任务，说明切换原因，不冒充刚上传任务的结果。
- 打印失败：展示浏览器内报告，记录失败原因；答辩后补 PDF 视觉验收。
